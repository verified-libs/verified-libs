New boards: first runs (2026-11-11)

First bench and stress runs on the three Nucleo boards from the DigiKey order. Same firmware, libraries (libs.lock), toolchain image and adapters as on the nRF5340; only the board layer (firmware/common/<board>/) differs. Records are in ~/lab-runs/ on lib-lab1.

The H723ZG runs at its reset clock on purpose: 550 MHz needs a supply configuration that matches the board, and a wrong one can lock the chip. Cycle counts are what the bench reports, so the comparison holds; flash numbers with the cache off include the reset-default wait states.

Stress (ISR <-> main, 50 000 values per library and direction)

~/lab-runs/stm32-stress-first-20261111T191247Z: single, block and zero-copy (dma) on each board, 9 runs, all valid: real libraries error-free, the negative control caught in every run, nothing starved. wizard97 as shipped (not ISR-safe by its own docs) fails on all three boards (761–7989 errors), as on the nRF5340. Interrupt every 160–668 core cycles (prescaler 0).

These are short runs, not a campaign.

Fix found on the way

The first G474 run stalled: TIM2 is a 32-bit timer, and when the interrupt acknowledged a new period that the counter had already passed, it counted on to 2^32 (about 100 s at 170 MHz / 4) before the next interrupt. common/stm32/tim2_stress.h now restarts the counter in that case (commit 6a58fbc), which matches the nRF5340's 8-bit timer behaviour. Two records made while an old test process still used the same board were discarded (~/lab-runs/invalid-overlap-20261111/).

Multi-producer / multi-consumer stress (evening)

SAM D20 Xplained Pro (not working yet)

Board layer written (common/samd20/): 8 MHz OSC8M, 0 wait states, SysTick timing, TC0/TC2 as the two stress timers, flash image only (32 KB RAM). Register values from Zephyr hal_atmel 8f95c79f (Microchip's headers). probe-rs cannot drive the board, so common/samd20/bin/probe-rs stands in with OpenOCD. Bench, stress and MP firmware build. On the board, SWD fails with "stalled AP operation" (also before our firmware was ever flashed), and a USB power cycle of its port did not clear it; it worked once after a manual replug. adapter serial crashes OpenOCD 0.12.0 with this EDBG, so the stand-in does not select the probe by serial. To check with the board in hand.
