MP stress test: where the interrupts land, random vs aimed (prototype)

2026-11-17, NUCLEO-G474RE (Cortex-M4F, 170 MHz), rb-mp-stress built with -DCOVERAGE=1 (a prototype build flag; the default image is byte-identical to the one before the change, checked). Owner's go the same day, after the question why the control is often not caught at the slow timer rates (prescaler 3 and 4): making the control easier to catch would hide that signal, so instead measure how well the test reaches each library's code, and try aiming the interrupts at it.

What was measured

  • Coverage. Every interrupt records the address it interrupted (the PC the core stacked), per library and interrupt (main.c vl_cov, a hash table of 4096 entries; none overflowed). cov_report.py maps each address to the library's instructions with the image's line info (code inlined from a library header counts as the library's), and counts per instruction boundary: how often an interrupt landed exactly there. Boundaries where interrupts are masked (after cpsid i / a saved PRIMASK, followed along every path, nested saves included, plus the one boundary right after the unmasking instruction, which the core never takes: seen as 0 there and everything one instruction later) are not counted: no interrupt can land there in any test. A basic block with at least one interrupt in it was executed; boundaries in blocks without any are listed apart (possibly never executed in this test, e.g. a retry path).
  • Aimed interrupts. Besides the timers, the main loop arms SysTick before each of its push/pop with a random delay of 1-160 cycles, and SysTick (highest priority) then pends interrupt A or B; interrupt A arms it the same way for B before its own push/pop (B preempting A inside an operation is the producer/producer resp. consumer/consumer race).
  • Prescaler 3 (the rate where the control is often missed), 300 000 values per library, the same seeds for random and aimed; one run each.

Reading

  • With random timer interrupts only 2-10 % of the interrupts land in the code under test; the rest land in the test's own loop. Aimed, the share is 2-4 times higher and the median count per boundary 2-20 times higher (more where the operation is short compared to the timer period), in the same run time.
  • The libraries that mask interrupts (pxq, RIOT tsrb, wizard97 + PRIMASK) have few boundaries where an interrupt can land at all; that is their design, and the table counts only those. The lock-free ones (DNedic, heapless) have many more, and there aiming matters most: heapless had 56 of 94 boundaries hit 10 times or more at random, 90 of 119 aimed, and fewer blocks never interrupted (102 -> 75-77 boundaries; the rest are likely retry paths that need a real collision).
  • The number per library is a measure the page could show: "every interruptible boundary of push/pop interrupted at least N times", per board, independent of the control.

Limits of the prototype

  • One board, one rate, one run per setting; the window (160 cycles) is fixed, not fitted to each library's operation length.
  • Recording costs a few dozen cycles per interrupt, so the timing differs slightly from the campaign image.
  • Aimed runs shift the balance (interrupt B pushes or pops about two thirds of the values).
  • The prototype builds for the STM32 boards (TIM2/TIM3 IRQ numbers) and ran on the G474 only. The nRF5340 and RP2350 need their timers' IRQ numbers; on the M0+ boards (G0B1, SAM D20) SysTick also serves as the cycle counter, so aiming there must be checked or done another way.
  • The table is read over the debug port (one image of all libraries per start, PER_LIB=0); for the campaigns it would go into the UART dump.

Records, tables and images: ~/lab-runs/cov-proto-20261117/ on lib-lab1 (*.cov.txt, *.elf, *.cov.json, report1.txt).

Port to all boards and one library per reset (same day, later)

The owner approved putting aimed runs into the campaigns (half of the prescaler 3/4 runs, coverage in every report) once the measurement ran on every board and with one library per reset. Changes:

  • Timer IRQ numbers for the nRF5340 (TIMER0/1), RP2350 (PWM wrap 0/1) and SAM D20 (TC0/TC2). On the M0+ boards (G0B1, SAM D20) board_init leaves SysTick running as the cycle counter of time_call(), which this test does not use; the first try there never aimed (the "already armed" check: 0 aims), so aim_init now stops it.
  • One library per reset (PER_LIB=1, the campaign way): the aim settings are run parameters in the "go" line (cov_aim, cov_window, cov_seed); after "dump" the host sends "dump2" for the table (common/vls_uart.h VLS_DUMP2, common/uart_host.py VLS_DUMP2=1). run.sh keeps one table per library with that library's image (<record>.cov.<n>.txt, elf/<sha256>.elf, <record>.cov.list). Images without COVERAGE stay byte-identical (checked on all six boards).
  • cov_report.py reads the per-library tables; RP2350 addresses (8 hex digits, which objdump prints unindented) were not parsed before.
  • campaign.sh: COVERAGE=1 by default, recording in the prescaler 3/4 runs only (cov_off per run: at prescaler 1 the recording, some dozens of cycles per interrupt, starved the SAM D20's main loop in a smoke test; at prescaler 3 it adds about 3 % interrupts per value there), aimed runs as above (which ones alternates per pass of the rotation), cov_report.py over all records at the end; summarize.py lists aimed runs apart and adds a coverage table.
