Four compilers on the STM32 boards (2026-11-12)

The libraries under test and their adapters built with four compilers, on the three STM32 boards (G474, H723, G0B1); harness, startup and link stay the Debian arm-none-eabi-gcc 14.2.1 with newlib-nano in every case (firmware/common/compiler.mk):

COMPILER= Compiler
gcc Arm GNU Toolchain 14.2.1 (Debian gcc-arm-none-eabi 14.2.rel1)
clang Ubuntu clang 21.1.8, GNU headers
st-gcc GNU Tools for STM32 14.3.1 (STM32CubeCLT 1.22.0)
st-clang ST Arm Clang 21.1.1 (starm-clang, CubeCLT 1.22.0), GNU headers

The ST compilers run from a local image that is never pushed (ST licence SLA0048; toolchain/st), and only for STM32 boards (its clause 4).

Correctness

ISR stress (single bytes, blocks, DMA zero-copy) with st-gcc and st-clang at -O2 (18 runs) and with st-clang-omax at -O3 (9 runs): all valid (control caught), 0 errors in every real library. Records: ~/lab-runs/st-compilers-20261112/<board>/ and ~/lab-runs/st-omax-20261112/<board>/.

Same code, mostly

Object code compared function by function (objdump -d, addresses stripped), 44 objects per build:

Pair G474 (M4) G0B1 (M0+)
st-clang vs clang 0 differ 0 differ
st-gcc vs gcc 11 differ 2 differ
clang vs gcc 40 differ 40 differ
  • ST Arm Clang 21.1.1 and Ubuntu clang 21.1.8 generate byte-identical code for these libraries with the same flags and headers. What ST adds is its runtime (newlib, libc++; not used here) and its optimisation presets (below).
  • GNU Tools for STM32 14.3.1 differs from Arm GCC 14.2.1 in small ways (operand order of a compare, register choice). In the bench the cycles are the same in every cell on the G474 and G0B1; on the H723 two cells differ (lwrb push 151 vs 145, micoring single-context block 30.7 vs 29.0 cycles/byte).

So, for these libraries, "ST's compiler" measures the same as the upstream compiler of the same family; the gcc/clang choice is what matters.

gcc vs clang (-O2, flash, cache on)

Sum of mean push + pop cycles (1 byte) over the 29 library builds:

Board gcc / st-gcc clang / st-clang clang vs gcc
G474 (M4) 3 848 3 980 +3 %
H723 (M7) 3 038 (st-gcc 3 044) 2 931 −4 %
G0B1 (M0+) 5 610 6 952 +24 %

On the M4 and M7 the two trade places library by library (clang is faster for lockfree spsc::RingBuf, FreeRTOS stream buffer, diffstorm; gcc for lwrb, Zephyr ring_buf, polycratia). On the M0+ clang is much slower for every library that uses C11/C++11 atomics: clang lowers each atomic load and store on ARMv6-M to a call to __atomic_load_N / __atomic_store_N (gcc inlines LDR/STR with DMB). Here those calls go to firmware/common/armv6m_atomic.c, which does what gcc inlines, after a switch on the memory order. Examples (push/pop cycles, gcc → clang): jnk0le 36/42 → 113/118, ETL queue_spsc_atomic 54/51 → 121/121, QuantumLeaps LFRB 69/61 → 174/154, rt-spsc 45/44 → 122/118, polycratia 39/46 → 124/129. Libraries without atomics (lwrb, ece-mohammad, TinyUSB, the interrupt-masking designs) are within a few cycles. A program built with clang for an M0+ has to supply these functions somehow; how cheaply it does so decides the cost of every atomic access.

All cells are in the appendix.

ST's Omax preset (COMPILER=st-clang-omax, -O3)

starm-clang --config=Omax.cfg, ST's speed preset shipped with the compiler: -O3 plus LLVM options for more inlining and unrolling, loop flattening, unroll-and-jam, DFA jump threading and inlined memcpy loads/stores. Compared with gcc and clang at -O3 (same harness flags). It changes 9 of the 44 objects against clang -O3. Sum of mean push + pop cycles over the 29 library builds:

Board gcc -O3 clang -O3 st-clang Omax Omax vs clang -O3 Omax vs gcc -O3
G474 (M4) 3 468 3 916 3 672 −6 % +6 %
H723 (M7) 2 731 2 981 2 866 −4 % +5 %
G0B1 (M0+) 5 101 6 896 6 780 −2 % +33 %

Almost all of the gain is in the two libraries that call memcpy in their single-byte path, lwrb and the FreeRTOS stream buffer, which fits the preset's inlined memcpy (not checked instruction by instruction) (G474 lwrb push/pop: clang -O3 222/212, Omax 138/133, gcc -O3 129/125); the other libraries measure the same as clang -O3. gcc at -O3 is the fastest of the three on every board.
